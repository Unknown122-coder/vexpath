# 05 · Roadmap and Milestones

Each milestone ends with something usable and demonstrable. Acceptance criteria are binary. Nothing from a later milestone starts until the current one's criteria pass in CI.

## M0 · Foundation (repo, tooling, fixtures) — **complete 2026-11-09**

Delivered:
- Monorepo as in `01-architecture.md § 5`: `uv` workspace with four library packages and two applications, `ruff` for lint and format, `mypy --strict` across every source tree, `pytest`. Python only, no Node toolchain.
- Domain models in `core.models`, with the product's central invariant enforced in code: a finding cannot be marked `not_affected` unless reachability actually proved it unreachable, or a human recorded a suppression.
- `core.ids` (ULID), `core.purl` (ecosystem-aware normalisation), `core.enums` (every closed vocabulary), `core.protocols` (injected clock, advisory source, object store), `core.snapshot` (reproducibility hashes, read and write).
- `sscp_db`: SQLAlchemy tables for the five global tables, engine helpers, Alembic baseline migration.
- `sscp_api`: application factory serving the JSON API and the HTML UI from one process, settings, structured logging with redaction, liveness and readiness, security headers, home page.
- `sscp_worker`: the `advisory.seed_snapshot` job, idempotent, with a command-line entry point.
- `sscp` CLI skeleton with the exit-code contract fixed and `sscp version` reporting capabilities.
- Frozen advisory snapshot (`testdata/advisories`, eight advisories) generated by `tools/build_test_snapshot.py`, covering every pipeline path the fixtures need: reachable, module-level, unused, dynamic-only, no-symbols, non-Python, withdrawn.
- Six fixture repositories with `expected.yaml` verdicts, covering every verdict rule in `03-reachability-design.md § 5`.
- Three fixture SBOMs: CycloneDX 1.6, SPDX 2.3, and a mixed-ecosystem document.
- Docker: one image with two process types, Compose bringing up Postgres, MinIO, migrations, the API and the seeded snapshot.
- CI: lint, format, types and unit tests on Windows and Linux; a Postgres job running migrations, `alembic check`, seeding, integration tests and a downgrade-and-upgrade cycle; an image build that proves liveness answers with no database present.

Acceptance met:
- 124 unit tests pass; lint, format and `mypy --strict` are clean.
- `docker compose up` yields a healthy API returning `/healthz`.
- The committed snapshot's integrity hash verifies, and CI fails if the snapshot and its generator disagree.

Deferred deliberately:
- The snapshot holds eight hand-built advisories rather than a few hundred real ones. Real advisories arrive with the OSV ingest in M1, which is the code that can fetch and normalise them; hand-transcribing hundreds now would produce a large fixture whose accuracy nobody had verified.
- `procrastinate` is not yet wired up. A worker loop with no scheduled job to consume would prove nothing; it arrives with `advisory.sync` in M1 (ADR-0003).

## M1 · SBOM + matching CLI (first usable tool)

Deliverables:
- `core.sbom`: CycloneDX 1.6 JSON/XML and SPDX 2.3 JSON/tag-value parsers with schema validation; native generators for Python lockfiles (`uv.lock`, `poetry.lock`, `Pipfile.lock`, pinned `requirements.txt`, `pdm.lock`) and for `package-lock.json` and `pnpm-lock.yaml`; Syft fallback.
- `core.advisory`: OSV ecosystem export loader, GHSA enrichment, EPSS and KEV enrichment, snapshot hashing; live client against the OSV API for the CLI when no snapshot is present.
- `core.vulnmatch`: PEP 440 and semver range evaluation, alias dedup.
- `core.report`: table and JSON output.
- `sscp sbom generate|validate`, `sscp scan --no-reach`, `sscp advisory sync|show`.
- Advisory sync worker job writing to Postgres; symbol-coverage metric scaffolding (counts of advisories with fix references by tier).

Acceptance:
- Parses every fixture SBOM in `testdata/sboms` and round-trips component counts.
- Matching agrees with `osv-scanner` on the fixture lockfiles (same advisory set, order-insensitive).
- `sscp scan --no-reach` on a 500-dependency lockfile finishes in under 30 seconds with a local snapshot.
- Report: percentage of PyPI advisories with a fix-commit reference by tier (so M2 starts with real numbers).

## M2 · Reachability for Python (the differentiator)

Deliverables:
- `advisory.patchdiff` job and `vulnerable_symbols` extraction with confidence tiers; curated-overrides YAML format.
- Python call-graph builder (`core.reach.python`): modules, imports, light assignment-flow inference, class-hierarchy analysis, conservative dynamic edges, opaque functions.
- Entry-point detection for console scripts, `__main__`, FastAPI, Flask, Django, Celery, Typer/Click, Lambda, ASGI/WSGI callables.
- Non-Python components resolve to `symbols_unknown` with reason `ecosystem_unsupported` and a visible capability note (ADR-0012).
- Dependency graph builder from archives; local cache; `callgraph.build` worker and global cache in object storage with `/callgraphs/bundle`.
- Verdict rules from `03-reachability-design.md § 5`; shortest-path evidence; `sscp reach`, `sscp scan` with reachability on by default.
- Benchmark harness: 30 public repos, frozen expected verdicts, zero-tolerance check on false `not_affected`.

Acceptance:
- All fixture repos produce the expected verdict and path.
- Benchmark: at least 90 % agreement on `confirmed`/`unreachable`, zero manually confirmed exploitable findings marked `not_affected`.
- Symbol coverage for PyPI advisories at or above 55 % (`high` + `medium`); if below, the curated path is prioritised before M3.
- 500-dependency scan with warm cache under 5 minutes on a 2-vCPU machine.

## M3 · VEX, attestation, policy

Deliverables:
- `core.vex`: OpenVEX 0.2.0 and CycloneDX VEX generation with impact and action statements generated from evidence; `sscp vex export`.
- `core.attest`: in-toto Statement v1, DSSE, Sigstore keyless signing (`sigstore-python`), Rekor inclusion proof, verification with identity/issuer constraints; `sscp attest sign|verify`.
- `core.policy`: CEL evaluation with the context from `04-api-and-cli.md § 1`; presets; `sscp policy test`.
- SARIF output.

Acceptance:
- Generated OpenVEX validates against the official JSON schema; `vexctl` reads it.
- `cosign verify-attestation --type https://openvex.dev/ns/v0.2.0 --certificate-identity … --certificate-oidc-issuer …` succeeds on an attestation produced in GitHub Actions.
- Policy presets behave as documented on the fixture results; a malformed policy exits with code 3 and a line-pointed error.

## M4 · Hosted platform and public pages

Deliverables:
- API (`/v1`): auth (GitHub OAuth, API keys), projects, scan upload and ingest worker, findings with evidence, suppressions, audit log, badge endpoint, public endpoints, webhooks, OpenAPI spec committed.
- HTML UI in the same app (ADR-0011): dashboard (projects, scans, finding detail with server-rendered path viewer, diff between scans, policy editor, API keys), public report page, package pages, badge rendering, docs site. Jinja2 templates, HTMX attributes, Tailwind compiled by the standalone binary.
- Row-level security, rate limiting, structured logging, tracing, Sentry.
- Deployed: one container on Fly.io or Render, plus Neon and R2; advisory sync on schedule.

Acceptance:
- Playwright for Python suite covers: login, create project, upload scan via CLI, view finding path, toggle public, badge reflects state within 5 minutes.
- RLS test: a user from org A cannot read any row of org B through any endpoint (automated negative tests on every tenant table).
- Every HTMX-driven action also works as a plain form submission with JavaScript disabled (tested with Playwright's `java_script_enabled=False` context).
- Public report and package pages render server-side with no client-side data fetching, verified by asserting the full content is present in the initial HTML response.
- Public package page for `requests` lists its advisories and extracted symbols.

## M5 · GitHub Action, distribution, launch

Deliverables:
- `apps/action` published to the Marketplace; SARIF upload; PR comment with diff; keyless signing from the workflow identity.
- `sscp` on PyPI with a signed release (SLSA provenance via the official generator); Docker image on GHCR.
- Dogfooding: this repository runs the Action on itself, and its README carries the badge.
- Launch docs: quickstart, "how reachability works", "how to verify our attestations", limitations page including the per-ecosystem capability matrix.
- Portfolio site entry linking to the public report of this very repository.

Acceptance:
- The Action runs on three external repositories (invite friends/colleagues) and their feedback is logged as issues.
- Release pipeline produces verifiable provenance (`slsa-verifier` passes).

## Post-v1 backlog (not scheduled)

- Coverage-upload dynamic cross-check.
- Re-evaluation webhooks when new advisories land (verdicts for the last scan recomputed from stored graphs).
- Go reachability by importing `govulncheck` output (no new analyser to write; the next ecosystem to add).
- JavaScript reachability, only as a scoped contribution from someone fluent in the language (ADR-0012).
- SSO, RBAC, on-prem installer.
- LLM-generated explanations of findings (explain only, never decide).
- License policy.

## Estimation note

Milestone sizes relative to each other: M0 small, M1 medium, M2 large (expect it to take as long as M1 + M3 together), M3 medium, M4 large, M5 small-medium. M2 is where the project succeeds or fails; schedule and attention go there first.
